六、贯穿项目始终的工程标准
━━━━━━━━━━━━━━━━━━

以下内容不能推迟到项目最后：

1. 安全与隐私
- 最小权限和后端对象级授权，防止 IDOR。
- 密码使用 PasswordEncoder，不保存或记录明文。
- Token、Session ID、密码、邮箱、IP、位置、私信内容不得进入普通日志。
- 不把敏感信息放入 JWT Payload。
- 不默认把长期 Token 放入 localStorage。
- CORS 使用精确来源，不能因调试直接允许全部来源。
- 根据认证方式正确处理 CSRF。
- 登录、注册、找回密码等接口考虑限流、防枚举和审计。
- 所有管理权限必须由后端验证，前端隐藏按钮不是安全措施。
- Markdown/富文本必须考虑存储型 XSS。
- 文件上传必须检查大小、数量、真实文件类型、文件头、随机文件名、访问权限和路径穿越。
- ZIP/Live2D 上传必须考虑 Zip Slip、解压炸弹和文件数量限制。
- 远程 Git/GitHub 导入必须考虑 SSRF、重定向、超时、下载大小和凭据泄露。
- 精确位置、好友关系、私信和上传文件属于高敏感功能，要有最小收集、可撤回、过期和删除设计。
- 不在仓库提交数据库、上传文件、日志、密钥或真实用户数据。

2. API 设计
- DTO 与数据库模型分离。
- 使用正确的 HTTP 状态码。
- 错误响应优先研究 Spring ProblemDetail/RFC 9457。
- 不为了形式机械地把所有响应包装成 code/message/data。
- 如果决定使用统一成功响应，必须先记录理由和代价。
- 分页必须设置最大 page size。
- 不向公开 DTO 暴露邮箱、密码摘要、本地路径、内部状态或审核备注。

3. 数据库
- 从第一张表开始使用 Flyway。
- 生产环境不依赖 ddl-auto=update。
- 事务放在合理的 Service 边界。
- 重要查询学习索引、EXPLAIN、锁、隔离级别和并发问题。
- 集成测试尽量使用 Testcontainers MySQL，避免只在 H2 通过。
- 数据库结构变化必须考虑回滚、旧数据和非空字段迁移。

4. 代码质量
- 按业务功能组织包，避免巨型 Controller/Service。
- Controller 处理 HTTP 和校验，Service 处理业务和事务，Mapper 处理持久化。
- 不复制粘贴权限判断。
- 明确命名、单一职责、依赖注入和可测试性。
- 不捕获异常后静默忽略。
- 日志使用参数化输出并进行敏感信息脱敏。
- 新依赖必须解释用途、替代方案和维护风险。

5. 测试
- 测试从第一个功能开始，不等到后期补。
- 覆盖正常、边界、异常、未登录、越权和对象所有权。
- 每个安全修复至少有一个能防止回归的测试。
- 覆盖率只是参考，关键行为是否被验证更重要。
